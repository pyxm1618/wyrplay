# WYRPlay 环境与发布手册

这不是新站 starter 教程。本文件描述当前 WYRPlay 仓库的开发、验证和发布入口，并保留在固定路径上供 release gate 读取。

## 本地开发

要求：

- Bun 1.4.4
- PostgreSQL 16 compatible database for database-backed tests

安装：

```bash
bun install --frozen-lockfile
```

开发：

```bash
APP_ENV=local APP_ORIGIN=http://localhost:3000 DATABASE_URL="postgres://..." bun run dev
```

不要把生产凭据放进仓库、聊天记录或测试数据库配置。

## 核心真源

- 站点身份：`src/config/site.config.ts`
- 功能开关：`src/config/features.config.ts`
- 路由/SEO：`src/config/routes.config.ts`
- 法律事实：`src/config/legal.config.ts`
- 正式题库：`content/question-bank/questions.json`
- Cloudflare runtime：`wrangler.jsonc`
- CI / deploy：`.github/workflows/ci.yml`

## 当前生产功能

生产 auth、email、commerce、subscriptions、credits 均关闭。GA4、Clarity 和 consent boundary 开启。

如果未来要启用 dormant capability，必须作为独立产品变更处理：配置、法律文本、外部资源、运行时 secret、定时任务、测试和运维文档同时验收。不要因为代码已经存在就认为生产能力已经开启。

## 数据库

使用 Drizzle migration 链。

```bash
bun run db:generate
bun run db:verify
bun run db:migrate
```

不要手写 migration 后冒充生成结果，不要用 schema push 代替正式 production migration。

测试 reset 只能指向隔离数据库。

## 验证

最小开发验证：

```bash
bun run format:check
bun run lint
bun run typecheck
bun run test:unit
```

涉及数据库、路由、安全、发布或平台边界的变更应追加相关 integration/contract/build，并以 CI 为最终提交门禁。

完整本地聚合门禁：

```bash
bun run verify
```

## Cloudflare

生产使用 OpenNext Cloudflare。

```bash
bun run build:cloudflare
bun run deploy:cloudflare
```

实际生产发布由 GitHub Actions 在 `main` push 后执行，并拒绝部署已经落后于远端 `main` 的 workflow SHA。

`wrangler.jsonc` 当前包含：

- production origin；
- Hyperdrive binding；
- incremental-cache R2 bucket；
- Cloudflare Images binding；
- analytics public IDs。

外部资源 secret 不应写入该文件。

## 发布前

使用 `docs/运维/上线检查清单.md`。

如果 commerce 仍关闭，不要为完成 checklist 伪造商户资源。Waffo 文档保留的是未来激活门禁，而不是当前生产已启用的证明。
