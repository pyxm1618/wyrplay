# WYRPlay 题库数据契约

版本：2.0
状态：Current SSOT

## 1. 真源

正式题库唯一真源：

`content/question-bank/questions.json`

运行时适配器：

`src/modules/would-you-rather/data/questions.ts`

可执行契约：

`tests/unit/would-you-rather/question-contract.test.ts`

文档不得另建第二份题库，也不得覆盖上述代码和测试定义的事实。

当前快照要求 512 条正式记录，且 512 条均为 `approved`。这个数字可以在未来经过正式编辑流程后变化；变化时同步测试，不通过手工修改本文制造“完成”。

## 2. Raw canonical schema

当前 JSON 记录使用以下字段：

```ts
interface RawQuestion {
  id: string;
  question: string;
  optionA: string;
  optionB: string;

  reviewStatus: "unreviewed" | "approved" | "deferred" | "rejected" | "retired";

  primaryCollection?: string;
  primaryAgeBand?: string;
  ageBands?: string[];
  relationships?: string[];
  scenarios?: string[];
  moods?: string[];
  difficulty?: string;
  topics?: string[];

  safety?: {
    kidsSafe?: boolean;
    classroomSafe?: boolean;
    familySafe?: boolean;
  };

  provenance?: {
    batch?: string;
    candidateId?: string;
  };
}
```

Formal production IDs currently use the `wyr-000001` style and are tested for uniqueness.

## 3. Runtime normalized schema

The runtime `Question` type exposes:

- `ageGroups`: `4-6 | 7-9 | 10-12 | 13-17 | 18+`
- `relationships`: `friends | family | couples | coworkers`
- `occasions`: `classroom | party | road-trip | dinner | date-night`
- `tones`: `funny | weird | deep`
- `difficulty?`: `easy | hard`
- `topics`: string values from the formal data
- `suitability`: kids / family / classroom / workplace
- `reviewStatus`
- formal-source compatibility fields such as `primaryCollection`, `primaryAgeBand`, `ageBands`, `scenarios`, `moods`, and `safety`

Do not narrow `Topic` to an invented fixed enum unless the production code and canonical source are intentionally migrated together.

## 4. Deterministic adapter rules

The current adapter:

- maps raw `4-6`, `7-9`, and `10-12` age bands directly;
- maps `teens` to `13-17`;
- maps `adults` to `18+`;
- maps raw `funny` and `weird` moods directly;
- maps raw `thoughtful` to runtime tone `deep`;
- maps only supported scenario values into runtime `occasions`;
- keeps raw topics as runtime topic strings;
- derives kids/family/classroom suitability from the raw safety booleans;
- leaves workplace suitability `unreviewed`;
- preserves raw provenance in `reviewNotes`.

If a raw label is not part of a normalized runtime union, the adapter may preserve it only in the raw compatibility fields rather than guessing a normalized meaning.

## 5. Identity and edit rules

Question ID is durable business identity.

- spelling, punctuation, or wording cleanup that does not change the dilemma may retain the ID;
- a change to premise, tradeoff, option meaning, or material assumptions requires a new ID;
- historic votes must not be silently moved from the old semantic question to the new one;
- retired/rejected/deferred questions may remain in historical data but must not be admitted to normal playable pools.

## 6. Publication gate

Normal playable pools require:

`reviewStatus === "approved"`

The product must fail closed for unreviewed content rather than filling empty states with unpublished questions.

Collection-specific selection is implemented by `getPlayableQuestionsByCollection`. The current collection keys are:

- `kids`
- `funny`
- `hard`
- `friends`
- `couples`

The executable selection code is authoritative. Do not duplicate collection logic in a document-only rule engine.

## 7. Kids rules

Kids selection requires approved content plus the product's child-fit/safety conditions.

Kids safety, classroom safety, family safety, and age fit are distinct facts. A question being harmless does not automatically make it classroom-safe or suitable for every child age band.

The Kids voting path has a stricter privacy contract than general-audience voting. Content schema changes must not weaken that privacy boundary.

## 8. Maintenance

Any change to the canonical schema must update, in the same scoped change:

1. `content/question-bank/questions.json` when data changes;
2. `src/modules/would-you-rather/data/questions.ts` when adapter behavior changes;
3. `src/modules/would-you-rather/types.ts` when runtime types change;
4. question-contract tests;
5. this document if the durable contract changed.

Do not keep migration ledgers for completed batches in the working tree. Git history and the canonical data's provenance fields retain that history.
