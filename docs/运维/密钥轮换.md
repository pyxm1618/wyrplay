# WYRPlay 密钥轮换

本文件由 release gate 要求存在。

## 原则

- 不在 Git、聊天、工单正文或截图中保存 secret。
- 泄露的 secret 不得因为“回滚方便”而重新启用。
- 新旧凭据是否允许重叠由具体 provider 决定，不能假设。
- 每次只轮换一个用途，验证后再吊销旧凭据。
- 记录 credential purpose / provider / rotation time / owner，不记录 secret value。

## 当前常见用途

根据实际启用情况，可能包括：

- database / Hyperdrive origin credential；
- Cloudflare API token；
- Better Auth secret；
- Google OAuth secret；
- Resend API key；
- Turnstile secret；
- internal job / cron authentication secret；
- retention encryption key；
- Waffo API / signing / webhook material。

Production auth/email/commerce 当前关闭，不代表相关 test/staging secret 可以长期复用或泄露。

## 通用轮换流程

1. 确认受影响环境和用途。
2. 在 provider 侧创建替代凭据。
3. 更新目标环境 secret store。
4. 部署或重启依赖该 secret 的 runtime。
5. 执行最小真实验证。
6. 确认旧凭据不再被流量使用。
7. 吊销旧凭据。
8. 检查日志和告警。

## 数据库

数据库凭据轮换必须确认 Hyperdrive/connection configuration 已指向新凭据，并验证 readiness 和代表性读写。

不要对生产使用会 drop/reset schema 的测试命令。

## Provider-specific feature

如果某 provider 当前未启用，不要为“演练”临时打开生产功能。使用隔离环境完成 provider 流程验证。
