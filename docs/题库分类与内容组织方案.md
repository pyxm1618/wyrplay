# WYRPlay 题库分类与内容组织方案

日期：2026-09-30。状态：分类建议稿，等待产品范围确认。本轮不生产题目、不修改题库、不实施分类迁移，也不编写代码或内容执行提示词。

## 1. 核心决定

保留用户熟悉的 Kids、Friends、Couples、Funny、Hard 等入口，但题库内部按不同维度描述同一道题。专题是符合条件的一组题及其编辑顺序，同一题可出现在多个专题，始终共用一个 ID 和投票结果。

Kids 需要进一步区分年龄；Classroom 和 Family 分别表示使用场景和参与者关系，可以与不同年龄交叉。Clean 表示内容标准，Hard 表示选择有多难，都不能替代年龄判断。

本版建议以 4 岁及以上的内容为覆盖范围，其中 4–6 岁面向成人朗读和带领。1–3 岁不设独立内容入口，这是本产品的范围选择，不是对儿童能力的普遍断言。

现有 104 道仅作为后续盘点样本。分类由用户需要决定，不能因为旧示意题库里没有某类题，就认定该类没有价值。

## 2. 本次竞品观察

定向查看了以下五个站点的实际页面。只研究内容组织和使用方式，没有验证它们的流量、排名、题量声明或教育效果，也不采集其题目建立自己的题库。

| 样本 | 实际观察 | 对 WYRPlay 的启发 |
| --- | --- | --- |
| [We Are Teachers 儿童题目页](https://www.weareteachers.com/would-you-rather-scenarios-elementary/) | 页面标为 Elementary School，内部包含搞笑、日常、季节节日、晨会、体育冒险、思考等分组 | Kids 是大入口；话题、用途、气氛可以交叉。但 Funny/Silly/Fun 等近义入口不必照搬 |
| [Twinkl 幼儿入学活动](https://www.twinkl.com/resource/eyfs-transition-would-you-rather-powerpoint-t-tp-1657143572) | 采用熟悉事物间的简短选择，说明由成人读出问题、孩子表示偏好 | 低龄内容需要不同的表述和带领方式，不能只把成人题删去脏话 |
| [PsyCat Games 生成器](https://psycatgames.com/app/would-you-rather-generator/) | 同一分类区并列 Fun、Hard、Deep、Superpowers、Food、Money 等 | 用户入口可以混合多个维度，但内部不能把气氛、难度和话题当成同一个单选字段 |
| [Conversation Starters 青少年页](https://www.conversationstarters.com/wouldyouratherquestionsteens.php) | Teens 下按学校、关系、衣着、食物、娱乐等分组 | 年龄决定生活经验，话题帮助选题；并不需要把所有年龄都继续拆成每一岁 |
| [Would You Rather for Kids 分类目录](https://wouldyourather4kids.com/categories/) | 主要按食物、动物、超能力、学校、运动等主题细分；还并列 Animals 与 Animals & Pets 等相近条目 | 可以借鉴主题覆盖，但要控制同义或高度重叠的分类，不以分类数量作为质量指标 |

没有发现一个应直接照搬的统一年龄标准。下文 4–6、7–9、10–12 的边界是 WYRPlay 的编辑建议，仍需未来逐题审校及实际使用反馈验证。

## 3. 先分清三种人

1. **操作者或带领者**：老师、家长、聚会主持人、自己打开网站的人。影响说明文案、朗读和 Presenter 使用方式，通常不决定题目属于哪个受众。
2. **回答问题的参与者**：不同年龄的孩子、朋友、家人、伴侣、同事。这决定选题范围。
3. **题目里的角色**：医生、老师、宇航员、海盗、名人等。这通常属于话题素材，不应逐个变成受众分类。

例如，老师带七岁学生玩，参与者年龄是儿童、场景是课堂。题目写到老师，不代表它适合课堂。面向老师本人回答的职业题，又是另一种使用需要，不能与学生课堂题混为一类。

本版不单独建设“老师本人题库”“家长本人题库”，也不按每一种职业、虚构角色或性别扩展导航。

## 4. 内部应区分的七个概念

这七个概念不意味着七排用户筛选器，更不意味着七张数据库表。

| 维度 | 回答的问题 | 本版建议 |
| --- | --- | --- |
| 建议年龄 | 题目的语言、经历和内容适合什么年龄？ | 4–6、7–9、10–12、13–17、18+；允许一题适合多个年龄段 |
| 参与关系 | 谁和谁一起玩？ | Friends、Family、Couples、Coworkers；无关系要求的题不必强行限定一种关系 |
| 使用场景 | 在什么活动里使用？ | Classroom、Party/Game night、Road trip、Dinner、Date night |
| 气氛 | 希望产生什么感觉？ | Funny、Weird/Imaginative、Deep/Thoughtful；不把近义词各建一类 |
| 选择难度 | 两个选项是否难取舍？ | Easy、Hard；一般题无需强行归入两端，默认无难度筛选 |
| 话题 | 题目谈什么？ | 首批控制为八个大主题，用于内容覆盖与去重；暂不占据主导航 |
| 内容适用性 | 能否在某一人群/场合放心使用？ | 按儿童、混龄家庭、课堂、职场的明确审核标准判断；未审核不等于适用 |

### 八个起始话题

- Animals & Nature：动物与自然。
- Food & Everyday Life：饮食与日常生活。
- Fantasy & Superpowers：幻想与超能力。
- School & Learning：学校与学习。
- Travel & Adventure：旅行与冒险。
- Hobbies & Entertainment：运动、游戏、音乐、影视和爱好。
- Relationships & Values：人际关系、记忆、价值取舍等。
- Work & Money：工作、职业和金钱。

一题可有 1–2 个主要话题。题中偶然提到的每个名词都不必加标签。季节节日、特定职业、名人/IP 等先作为后续内容专题候选，不预建大量空分类。

### 需要纠正的几种混淆

- **Easy 与低龄不同**：成人生活问题可能很容易选择，但孩子未必理解其背景。
- **Hard 与深奥不同**：儿童熟悉的两种活动也可以很难取舍；Hard 不需要死亡、创伤或晦涩词汇。
- **Deep 与成人不同**：关于公平、友谊的简单问题可以适合较大儿童；年龄和语言仍需单独审核。
- **Clean 与儿童/课堂适用不同**：无粗口、无露骨内容仍可能涉及经济压力、隐私、疾病或损失。
- **Adults 与露骨内容不同**：本版成人题关注工作、生活和价值选择，不引入 Dirty/NSFW 产品线。
- **School 话题与 Classroom 场景不同**：关于同学、老师的题不自动适合公开回答；宇宙、动物等话题也可适合课堂。
- **Family 与 Kids 不同**：Family 要让多代人都能参与，而不只是给儿童题换标题。

## 5. 年龄到底分多细

### 推荐：保留 Kids 总入口，内部先分三档

| 用户入口 | 编辑重点 | 边界 |
| --- | --- | --- |
| Kids · Ages 4–6 | 成人朗读；短句；熟悉事物；单一、具体的选择 | 不依赖独立阅读、复杂条件、讽刺、成人经历或遥远后果 |
| Kids · Ages 7–9 | 日常、学校、动物、简单幻想；能用一句话解释选择 | 避免多重反转、复杂概率和过多背景知识 |
| Kids · Ages 10–12 | 更丰富的幻想、爱好、友谊、公平与简单取舍 | 不默认拥有社交账号、恋爱或成人消费经历 |
| Teens · Ages 13–17 | 学校、兴趣、同伴、独立性与未来选择 | 先以较年轻青少年也能理解的内容为公共基线，不默认驾驶、饮酒或全职工作经历 |
| Adults · Ages 18+ | 工作、生活安排、关系及价值选择 | 不自动导向露骨、羞辱或强迫披露隐私的内容 |

年龄是选题参考，不是认知诊断，也不要求收集生日、创建账号或引入年龄验证流程。成人朗读不意味着本版必须做语音或图片生成。

### 不建议本版继续拆的项目

- 1–3 岁：不建设独立题库与入口。该范围需要另行评估成人引导、图片或实物选择等体验。
- 每个单岁、每个年级：先不做；不同国家的年级与年龄也不完全相同。
- 13–15 与 16–17：先不建两个独立入口。若未来内容在驾驶、升学等经历上出现明确差异，再评估。
- 成人按 18–24、25–34、35+：先不做。当前按关系、场景和话题筛选更直接。
- 男孩/女孩、男性/女性：不作为默认选题维度；兴趣和参与关系更贴近当前任务。

不要给同一题生成五个仅更换年龄标题的版本。相同题意共用 ID；如果改写后假设或 A/B 的含义变了，则是新题，不能沿用旧投票。

## 6. Kids、Family、Classroom 如何交叉

它们不用互相争夺“父分类”，而是从同一题库组合出不同集合。

| 用户需要 | 组合逻辑 | 审核重点 |
| --- | --- | --- |
| 给七到九岁学生做课堂热身 | 年龄 7–9 + Classroom + 适合热身的精选集合 | 全班能听懂、能公开回答，不比较同学、不要求私密披露 |
| 全家在路上玩 | Family + Road trip + 按最小参与年龄控制内容 | 多代人能参与、便于口头理解；题目不必都谈汽车或旅行 |
| 朋友聚会想搞笑 | Friends + Party + Funny + 对应年龄 | 玩笑不依赖羞辱、泄密或让某个参与者难堪 |
| 同事第一次见面破冰 | Coworkers + 工作场合审核 + Icebreakers 精选集合 | 低压力、低隐私要求；不能仅筛“工作话题” |
| 伴侣在约会时深入聊天 | Couples + Date night + Deep + 对应年龄 | 关系假设合适；不自动混入只能由已婚/有孩子的人回答的题 |

这里示范的是筛选关系，不是已经审核通过的题集。未匹配到合格题时必须明确显示无结果，不能偷偷放宽年龄或混入成人题。

### 混龄和默认值

- Family 根据最小参与年龄控制理解与内容下限，再由编辑挑选适合共同讨论的题。不能把“有成年人在场”作为放入成人题的理由。
- Kids 总页可以展示按年龄标注的目录；默认可玩集合应是明确审过的跨儿童年龄精选，不直接合并三档后无标注随机抽取。
- 4–6 岁内容明确提示成人朗读。其与 10–12 岁的题目不需要完全隔离，但交叉适用必须有审核依据。
- “不限风格”只取消气氛约束，不取消年龄、关系或场景限制。

## 7. 用户看见什么

### 第一层：熟悉的快捷入口

保留已有 Kids、Funny、Hard、Friends、Couples 五个核心专题。后续内容到位后，可在页面内加入 Teens、Adults、Family、Classroom、Work 等入口；这些入口不自动产生新 SEO 页面。

导航可以采用用户熟悉的混合词汇，因为它们是预设好的选题条件；内部数据仍分别表达年龄、关系、场景等事实。

### 第二层：进入后只出现相关选择

- 进入 Kids：突出年龄，随后可选 Classroom/Family 等使用方式与 Funny/Hard 等风格。
- 进入 Family：突出最小参与年龄，再选 Dinner/Road trip 等场景。
- 进入 Classroom：突出学生年龄和合适的热身/讨论集合。
- 进入 Friends/Couples：提供年龄与气氛筛选；不把具体关系状态当成默认事实。
- 进入 Funny/Hard：仍可缩小到儿童、朋友、家庭等范围，风格不能覆盖适用性约束。

不用每次要求用户填完所有条件才能玩。直接可玩，筛选按需展开；界面只显示当前有效条件和真实题数。

### 第三层：编辑用信息

话题、适用性理由、来源、近似题关系和审核记录先用于内容维护，不全部做成用户标签墙。Classroom、Family、Work 等公开标记必须有具体审核依据。

## 8. 专题、预设、SEO 页面如何对应

- **基础属性**说明题目适合什么条件。
- **专题/预设**从符合条件的题里选出有节奏、有覆盖的集合。例如 Icebreakers 是低压力的破冰集合，Birthday/Sleepover 是聚会细分集合。
- **SEO 页面**是少量有明确搜索需要、内容足够完整的专题展示页。

不把每个标签变成 URL，不把每一种交叉组合做成落地页，也不要求一个分类只能有一个父节点。当前五个专题 URL 保留，儿童年龄子组先在 Kids 页内实现。

Kids 与 Classroom 等入口分享题目不算内容重复建设：题目只有一份，页面筛选和编排不同。各专题需要自己的使用说明和选题理由，不能整页仅替换标题。

## 9. 现有 21 个标签的逐项处理建议

以下均是建议归位，等待本方案确认；本轮没有删除、改写或批量迁移任何标签和题目。

| 原标签 | 建议归位 | 处理理由 |
| --- | --- | --- |
| kids | 年龄总入口，下分三档 | “儿童”过宽，朗读要求和题目背景不同 |
| teens | 年龄入口 13–17 | 独立生活经验和语言需求 |
| friends | 参与关系 | 朋友可以处于不同年龄 |
| couples | 参与关系 | 关系不等于年龄，也不默认结婚或育儿 |
| family | 混龄参与关系 | 家人共玩需要按较小参与者控制内容 |
| adults | 年龄入口 18+ | 不与 NSFW 绑定 |
| coworkers | 参与关系/Work 预设 | 需要工作场合适用审核，不能仅按职业词筛选 |
| classroom | 使用场景 | 必须与学生年龄和公开回答适用性组合 |
| party | 使用场景 | 年龄与参与关系仍需独立控制 |
| road-trip | 使用场景 | 便于口头玩，不局限于旅行话题 |
| dinner | 使用场景 | 家庭、朋友或伴侣都可在用餐时玩 |
| date-night | 使用场景 | 不能据此假定双方已婚、同住或育儿 |
| icebreaker | 活动目的形成的精选预设 | 重点是低压力、易加入，而不是固定地点 |
| birthday-party | Party 的活动细分，暂不单开入口 | 先保留用途信息，内容足够不同再扩展 |
| sleepover | Party 的活动细分，暂不单开入口 | 年龄和私密程度需审核，不自动沿用成人聚会内容 |
| funny | 气氛 | 可与多个年龄、关系、场景交叉 |
| hard | 选择难度 | 不等于成人、死亡话题或阅读困难 |
| deep | 气氛/讨论深度 | 儿童也可有适合其年龄的思考题 |
| easy | 选择难度 | 不等于低龄；与阅读难度分开判断 |
| weird | 气氛/想象方向 | 不自动归入恶心、恐怖或不适内容 |
| clean | 内容审核标准，暂不作为主分类入口 | 不能保证儿童、课堂、职场全部适用 |

覆盖对账：21 = 已批准执行 0 + 已完成归位分析、等待确认 21 + 确认删除 0 + 尚未分析 0。保留旧标签及题目，后续迁移需另做逐题对账。

## 10. 什么时候值得更细

同时满足下面条件，才增加公开细分入口：

1. 用户会因此做出不同的选题决定，能用一句话说明差异。
2. 有不同且可执行的编辑标准，不是同义词换名字。
3. 有足够的独立合格内容。建议每个公开子入口至少能提供 15 道已审题，作为本产品的可玩性下限，不是 SEO 标准。
4. 不需要复制另一组的大部分内容来制造区别，也不会使导航和筛选明显难用。

缺内容时可以保留内部分类计划，页面不展示空入口；也不能为达到数量放行未审核题。是否增加 SEO 页面，还需要另行判断搜索需求，本次竞品研究没有证明任何关键词搜索量。

本版只对儿童年龄做必要细分；暂不铺开每个年级、职业、家庭身份、关系阶段、节日和兴趣的独立频道。

## 11. 下一步范围

先确定本方案中的年龄边界、七个概念、公开入口与审核标准，再形成一份共享的分类说明。之后代码 AI 与内容 AI 使用相同的标签含义和 ID 规则。

内容任务届时先盘点现有题库的覆盖、适用性和缺口，再决定修订与补充题目；代码任务按已确定的条件组合和预设来实现。当前仍停留在分类设计，不提前生产题库。
