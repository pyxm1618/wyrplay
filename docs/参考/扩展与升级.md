# WYRPlay 扩展与升级规则

本文件保留在固定路径上供 release gate 读取。它只描述当前 WYRPlay 如何安全改变平台能力。

## 原则

1. 产品需求优先，不因为底层 starter 曾经支持某能力就默认开启。
2. 先确认当前 production feature flag，再判断变更是否影响真实用户。
3. 平台能力升级必须保持 product-module / platform 边界。
4. 外部 provider 的真实契约必须以当前版本和真实资源验证，不凭旧文档猜测。
5. schema 变更使用向前 migration；破坏性变化必须有兼容和恢复方案。

## 依赖升级

当前关键版本均被精确锁定。升级 Next.js、React、Better Auth、OpenNext、Wrangler、Drizzle 或 Waffo 时：

- 先阅读对应版本的 breaking changes；
- 更新 lockfile；
- 跑 typecheck、unit、integration、contract、build；
- 涉及 Cloudflare 时跑 `build:cloudflare`；
- 涉及 provider 时补真实 contract 验证；
- 不把依赖升级和无关产品重构放在同一个 PR。

## 启用 dormant feature

Production 当前关闭 auth/email/commerce/subscriptions/credits。

任何一个从 false -> true 的变更都必须同时检查：

- runtime env / secret；
- route exposure；
- legal disclosures；
- scheduled jobs；
- database migrations；
- provider resources；
- browser flow；
- rollback path；
- operating runbook。

## Commerce

Waffo 激活前必须满足 `docs/参考/waffo-合约与验收.md` 的真实资源门禁。不得为了通过配置而设置未经真实验证的 activation flag。

## Documentation

只有 durable current-state rules 留在工作树。一次性 migration plan、审计报告、截图验收、round notes 和 closeout 进入 Git history，不创建 archive 目录。
