# WYRPlay 下一版产品方向与现状核查

日期：2026-09-30。性质：基于当前代码和线上观察的建议稿，不代表功能已经实现或版本通过验收。

分类专题补充：见 [题库分类与内容组织方案](./题库分类与内容组织方案.md)。后续先确认年龄、参与关系、场景及审核标准，再拆分代码与内容执行任务；本文件中的分类建议不应直接作为批量打标签规则。

## 1. 版本目标

让英文用户无需注册、付费或学习规则，就能找到适合当前场景的好题，完成选择、查看本站真实投票结果，并继续玩；老师、家长和聚会主持人能把同一批题用于现场讨论。

本版围绕三个交付物收口：**经过审校的正式内容、完整的找题与游玩体验、可靠的匿名投票。** 扩充题量可以后续做，但本次发布内容的质量不能后置。

保留目前的视觉方向、Next.js/React、PostgreSQL/Drizzle、六个核心 SEO 页面。不引入账号、付费、房间或内容后台。

## 3. 对旧提示词的取舍

### 采纳

- 免费免登录，优先补全核心玩法；不添加社区、实时房间、支付、AI 出题和 CMS。
- 使用永久 question ID；题意或 A/B 含义改变后新建 ID，避免旧票与新题混用。
- 匿名投票写数据库；同一匿名标识对同一题只有一个当前选择，可以改票，重复请求不增票。
- 保留现有核心 URL 和服务端正文，分类交互不批量制造 SEO 页面。
- 迁移、真实数据库测试、浏览器验证和 SEO 回归都是交付组成部分。

### 调整

1. **正式题库的质量本版完成。** 不批量灌入几百道题，但也不能以“临时 seed”作为正式内容交付。先审完现有 104 道，修复明确问题，只有覆盖存在真实缺口时少量补题。
2. **SEO 基线以当前 main 和生产为准。** 旧提示词提到的 `Play, Vote & Compare Answers` 已不是当前标题，不应机械恢复旧版本。
3. **静态内容可以是真实正式内容。** 题库随代码维护适合当前规模；用户行为统计必须持久化。把题库搬进数据库本身不会提升题目质量。
4. **分类、目录与 Arena 使用同一个当前题集。** 仅给分类文字加按钮还不够，筛选后 Next/Random/Presenter 必须继续使用该题集。
5. **投票失败和请求乱序纳入主流程。** 不能把请求失败显示成 0 票，不能把前一道题晚到的结果显示在下一题。
6. **Presenter 本版明确为现场展示。** 现场通过口头讨论、举手完成选择，不把主持人的一台浏览器当成多人投票，也不加第二套投票模式。
7. **数据表述限于本站收到的投票。** 不宣称全球民意、真实独立人数或严格的一人一票。清除 cookie、换浏览器可能形成新的匿名身份。

## 4. 当前内容基础与问题

### 数量事实

| 范围 | 当前数量 |
| --- | ---: |
| 全库 | 104 |
| 首页可玩及目录 | 50 |
| Kids 专题 | 27 |
| Funny 专题 | 30 |
| Hard 专题 | 28 |
| Friends 专题 | 19 |
| Couples 专题 | 26 |

专题有重叠，不能相加当成独立题数。当前精确 audience 标签：Kids 27、Teens 5、Friends 24、Couples 26、Adults 19、Coworkers 3、Family 0。Friends 专题 19 道与 audience 24 道来自不同筛选条件，应统一面向用户的含义。

### 已发现的具体问题

- `wyr-f11`：`Polite polite golf applause upon sitting` 重复单词。
- `wyr-k20`：题干是放弃 television，选项扩展成 `No screens or TV`；两种约束不等价。
- `wyr-h13`：题干是知识与分享的取舍，选项 B 加入 `full social warmth`，给其中一侧额外增加优势。
- `wyr-f15`：题干用“7 年前”，选项固定 `2017`，会随时间失去一致性。
- 部分题目同时有 Kids/Friends collection 标记但被单一 audience 条件排除。这说明 audience 不能同时承担“唯一归属”和“适用人群”的全部职责。

### 正式内容验收

逐题记录：ID、原文、保留/修订/暂缓/淘汰、理由、适用标签、修订是否改变题意、修订后的复核结果。每次筛除都要有题目级理由，未审题目保留为未审。

检查只围绕实际内容质量：

- 英文自然、题干与选项一致，选项不过度添加假设。
- 两侧有可讨论的取舍，避免明显一边倒及换词重复。
- Kids、Family、Classroom、Coworkers 的适用性分别审核；Clean 与 Funny/Deep 可以同时成立。
- 题量、适用年龄、编辑质量和原创性声明有依据。不以自动生成来源替代质量判断，也不宣称未经核实的独家原创。
- 不设 SEO 凑字数或凑题量指标；保留当前 Kids `25+` 标题时，该专题必须有足够的合格题目支持。

实施时允许 audience/occasion/style 改为简短的多标签数组，并逐题迁移；无需分类管理后台、标签关系表或通用分类框架。

## 5. 本版应完成的产品范围

### A. 找题与浏览

- 将专题快捷入口及分类放在目录前，避免先滚过 50 道题。
- 首页提供正式发布题库的找题入口，不把“全部”限定为文件的前 50 道。
- 增加简单关键词搜索，匹配题干和 A/B；约百道题直接内存过滤即可。
- 每个筛选维度只选一个值，维度之间取交集；显示当前筛选、实际匹配数量、清除和空结果说明。
- 五个既有专题继续使用真实链接；其余分类筛选当前题集。无额外筛选索引页。
- 目录点题后加载准确 ID、移动至 Arena，并把键盘焦点移到合适位置。

### B. 持续游玩

- A/B 可点击也可键盘选择；选择、改选的规则完全一致。
- Next 在当前题集中前进，Random 不返回当前题；空集、仅一题、走完题集都有明确行为。
- 推荐使用一次会话的打乱顺序避免频繁重复，题集走完后明确提供再玩一次；不引入推荐算法。
- 切题时立即清除旧题的展示状态，按新 ID 读取投票状态；晚到响应不能覆盖当前题。
- 支持跳过题目。未投过不展示比较结果，已投过恢复选择及真实结果。
- 移动端压缩装饰性留白和标签，优先让用户看到题目、两个选择和下一题。长题仍可自然滚动。

### C. 匿名真实投票

- 服务端签发随机匿名 cookie，按需建立，使用第一方、HttpOnly、Secure、SameSite 设置；不需要 email、IP 身份或指纹。
- `wyr_votes` 保存 `question_id`、匿名标识、A/B、创建和更新时间；唯一约束为 `(question_id, anonymous_voter_id)`，数据库限制选项只能为 A/B。
- 写入前确认题目存在且已发布。服务器计算计数和百分比，客户端只提交 ID 与 A/B。
- 使用 upsert 或等价事务完成同选幂等、改选更新。初期直接查询该题计数，避免维护第二套易漂移的累计计数。
- 只请求当前题，接口返回选择、A/B 数量、total；个人状态禁止共享缓存。
- 处理提交中、成功、失败、重试；提交失败不显示已保存，也不以随机数或 0 代替不可用数据。
- 重复点击、网络重试和切题需要有一致结果；不扩展为复杂防作弊。
- 使用现有服务端基础做输入校验、同源请求限制和基本频率限制，避免新增风控服务。

### D. 展示与基础体验

- Presenter 支持打开、关闭、Escape、上一题、下一题及对应键盘操作；按钮与快捷键的首尾边界一致。
- 对话框有正确焦点进入、焦点约束和退出恢复，长题与小屏可滚动。
- 375px 有简洁菜单，能到 Play、Questions 及五个专题。
- 主题首次加载和刷新一致，控制组件状态与页面实际主题一致。
- 保留现有视觉风格，修复实际对比度、触控及焦点问题，不做全站视觉重建。

### E. 内容承诺与上线基础

- 删除或改写用户可见的模板话术、实现术语和无依据的保证；README 增补 WYR 运行、内容维护与发布说明。
- 核对并停用不属于本产品的 `overlap-pro` 商品配置；无需拆除整个支付平台或批量删库表。
- 隐私说明准确描述 cookie、主题、投票选择与保留方式；核实当前仍标为 draft 的真实经营主体和联系方式，不编造事实。
- 对齐 Kids 页面的 5–12 岁内容描述、现有配置中的 minimumAge 13 与实际使用对象；这是当前文案/产品边界待明确项，不在本轮推导法律结论或设计儿童账号。

## 6. 最小架构选择

推荐继续采用 **代码维护题库 + PostgreSQL 保存投票**。

```text
正式题库文件（唯一内容来源、稳定 ID、发布审校记录）
    ├── 首页和五个专题的服务端 HTML
    └── 同一页面的筛选 / 目录 / Arena / Presenter
                         │ 当前题 ID
                  Next.js Route Handler
                         │ 校验、匿名身份、改票、统计
                 WYR 服务端投票逻辑
                         │
                  现有 Drizzle / PostgreSQL
```

- `src/modules/would-you-rather` 继续拥有题库规则、交互状态和投票业务。用普通函数与小范围共享状态，不增加 Redux、微服务或 commerce 式多层领域架构。
- SSR 正文读取正式题库，浏览内容不依赖投票数据库可用；数据库不可用时仍可浏览和现场展示，投票明确提示暂不可用。
- 数据库代码保持 server-only；客户端公开入口与服务端入口明确隔离。产品 schema 纳入统一 Drizzle 迁移与测试入口，不让平台模块反向依赖 WYR UI。
- 建议两个按题接口：读取当前题投票状态、提交/更新该题选择。不需要全库统计接口、轮询或 WebSocket。
- 题库文件是正式内容来源，SQL migration 是表结构来源；不同时维护文件和数据库两份可独立修改的题库。
- 投票上线后保存旧 ID/语义记录；退役题不出现在可玩列表，历史票不自动迁移到新题。修改含义新建 ID，拼写修正可保留 ID。

备选是题库与投票全部入库：适合已经需要不部署就更新题目、多编辑人员或运营工作流的情况；目前尚无这些需求，会增加导入、同步及 SSR 读取工作。全静态加浏览器计票则无法满足跨访客累计结果，应排除。

## 7. SEO 保护边界

当前基线：

- Title：`Would You Rather Questions – Play Fun Questions Online`
- Description：`Browse Would You Rather questions for kids, adults, couples, friends and parties. Pick A or B, play instantly, and find the perfect dilemma for any group.`
- H1：`Would You Rather Questions`
- 主关键词：`would you rather questions`
- 正式 origin：`https://www.wyrplay.com`；裸域访问会跳转到 www。
- sitemap 当前含首页与五个核心专题，共六项。

本版保留上述定位与 URL，按实际发布内容更新正常的修改时间。内容编辑、调整首页区块顺序、减少冗余话术都可以进行；SEO 保护不能成为保留错误内容或无用交互的理由。

搜索和筛选保持页面内状态，不生成可抓取参数组合。六个页面保留可抓取正文与专题内链，不因接入数据库变成只有加载动画的空页面。

Google 的[内容指引](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)强调内容是否对用户有用，并没有优选字数；[筛选导航指引](https://developers.google.com/crawling/docs/faceted-navigation)说明大量筛选 URL 可能造成无效抓取。因此本版不靠堆题、堆段落或批量新建分类页扩张。

## 8. 实施顺序与封版条件

### 顺序

1. 先复核生产按钮无反馈、建立当前 SEO 基线和产品验收清单；同时确认隔离测试数据库与生产迁移方式。
2. 审核现有 104 道题并完成发布集合、稳定 ID 和标签调整。内容语义先确定，再开始积累真实票。
3. 建立真实投票服务与迁移，再接入共享题集、筛选搜索和 Arena 完整状态。
4. 修复 Presenter、手机导航、主题、错误提示及用户可见模板文案。
5. 用下列固定验收通过后封版。只追加阻断核心需求、数据正确性或发布的 P0/P1；新的产品想法进入后续版本。

### 固定验收

| 范围 | 必须证明 |
| --- | --- |
| 内容 | 104 条原始记录都有明确审校状态，计数对账；发布集合逐题通过；题干与 A/B、专题数量和承诺一致 |
| 找题 | 搜索、筛选、清除、空结果、目录选题工作；Arena/Next/Random/Presenter 共用题集 |
| 真实票 | 隔离测试库中两身份产生 1/0、1/1，A→B 后为 0/2，再投 B 仍为 0/2；数据库读取与 UI 一致 |
| 投票异常 | 重复、并发、改票、刷新、跨页面同题、请求失败与乱序都有明确正确结果 |
